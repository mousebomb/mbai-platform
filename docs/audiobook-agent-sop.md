# 有声书 Agent SOP（文本预处理 → 调平台合成）

给"把小说变成有声书"的 Agent 看。平台只负责「一段文本 + 一个音色 + 一句指令 → 一个 wav」，
**所有需要理解内容的判断都在这里**。照这份 SOP 做，才能听得出是"朗读"而不是"念字"。

- 适用能力：`audio.tts/cosyvoice2-segmented`（首选，逐句）、`audio.tts/cosyvoice2-instruct`
- 相关文档：`AGENTS.md` §5.3（manifest 契约）、日志仓库的 `2026-10-27_PC_tts-instruct.md`（instruct 用法与实测）

---

## 0. 一句话原则

**用户看不见原文，只听得见声音。** 所有书面标记（省略号、破折号、括号、QQ 聊天格式）
要么被翻译成能听懂的口语，要么就不该被念出来。判断标准只有一条：

> 一个没读过原文的人，听完这段能不能知道"发生了什么"？

---

## 1. 七步流程

```
原文
 ├─ 1. 清洗书面格式（去 markdown / 去聊天前缀 / 合并碎片行）
 ├─ 2. 角色识别（谁在说话 → 音色映射）
 ├─ 3. 发音替换（网络用语、多音字、数字）
 ├─ 4. 消歧（省略号 / 破折号 / 括号补充语）
 ├─ 5. 按情绪分段（一段一个 instruct）
 ├─ 6. 逐句合成（cosyvoice2-segmented）
 └─ 7. 自检 + 合并
```

---

## 2. 清洗（第 1 步）

| 原文形态 | 处理 | 理由 |
|---|---|---|
| `“角色A:这也太离谱了吧。”` | 去掉引号和 `角色A:`，**只留台词**；角色名单独记录用于第 2 步 | 念出角色名会变成"播报腔" |
| `【群名片：项目已发布上线】` | 同上，去 `【】` 和角色前缀 | 这是聊天框的排版，不是正文 |
| 空行、单独一行 `…` / `……` | 不送合成，交给第 4 步处理 | 空段落合成出来是无意义的气音 |
| markdown 标题 / 加粗 / 列表符 | 全部剥掉 | `#` `**` 会被念成"井号""星号" |
| 一行只有动作（`他噼里啪啦打键盘。`） | 保留，作为旁白 | 这是叙事，不是对话 |

**碎片句必须合并**：切分后 `len < 6` 字的句子并回上一句。单字句合成出来只有一个音节，
既没有韵律，也给模型更多机会把指令念进去。

## 3. 角色识别与音色（第 2 步）

```yaml
# 角色映射表（每个项目一份，人工维护；未登记的一律走旁白音色）
roles:
  旁白:      {voice: <旁白音色>, instruct: 平静自然的旁白语气，像在讲故事}
  角色A:     {voice: <甲音色>,   instruct: 轻松调侃，像朋友聊天}
  角色B:     {voice: <乙音色>,   instruct: 平稳，偶尔带点无奈和自嘲}
  角色C:     {voice: <丙音色>,   instruct: 轻缓，带一点神秘感}
```

规则：

1. **对话行**用该角色的音色 + 该角色的 instruct；**当作旁白念会串味**。
2. **未登记的角色**一律走旁白音色，并在输出日志里记一条（别静默降级，否则后面查不出来）。
3. **同一段里连续多句同角色**，可以合并成一个任务，但**不要跨情绪合并**（见第 5 步）。
4. 音色必须有区分度：男声只有 118 / 134 Hz 两个时，两个男性角色会听混。加角色前先确认
   音色库里有对应的性别和年龄档（缺口只能用参考音频补，blend 补不出来）。

### 3.1 选角判据：主角要「少年/少女质感」，不要「播音质感」

实测结论（同一批候选、同一条文本）：

| 候选来源 | 特征 | 适合 |
|---|---|---|
| 朗读语料（AISHELL 一类） | 字正腔圆、播音腔重 | 旁白、主持人、老师 |
| 众包口语（Common Voice 一类） | 气息更「生」、年龄感更真 | 主角、同学、同龄角色 |

- **F0 和谱质心测不出「像同龄人」**：两个男声候选的 F0 与亮度几乎相同，
  听感差别全在音质；靠指标排序选角会选错。
- 主角试音时至少放 3~4 个候选，**必须人耳定**。
- 女声池如果只有朗读语料，就先取 F0 最高的那个当女主，再从众包池补角色。

### 3.2 已定角色：写成配置，不要写进代码

```yaml
roles:
  女主:
    voice: <音色名>          # VoiceDesign 造的卡或音色目录里的 wav 名
    instruct: 用清脆甜美的少女音说话，带笑意，语速稍快，尾音轻轻上扬。
  男主:
    voice: <音色名>
    instruct: 用明亮有活力的少年音说话，语速稍快，带一点笑意。
  旁白:
    voice: <音色名>
    instruct: 用温和沉稳的男声讲故事，语速正常，句尾收干净，不要播音腔。
```

四条实测约束：

1. **同一张卡换文本，F0 会漂**：抒情段落 250 Hz、中性叙述 270、急切对白 300。
   觉得「变小孩了」不是音色跑了，是模型跟着情绪抬了音高。
2. **instruct 压不住音高**：给男主加「音高偏低一些，胸腔共鸣明显」后，
   32 字长句 180 → 143 Hz（有效），但 7 字短句 133 → 173 Hz（反而更高）。
   短句上采样噪声大于指令效果，**别指望用一句指令把嗓子拧到位**。
3. **一条硬规则：同章角色之间的 F0 至少差 40 Hz**。男旁白 107 / 女主 253 很安全；
   但两个声线接近的卡（比如 209 与 194）**不能同章**，要么换卡，要么拆章。
4. **VoiceDesign 卡全部是凭空生成的**（一句文字描述 → 新音色），和真人录音无关；
   带真人来源的只有 `blend_*`（两段参考音频插值）那几个音色。

## 4. 发音替换（第 3 步）

**前提**：CosyVoice 是字符级 text token，**不吃拼音**。所以"注音"只能靠**同音字替换**，
效果靠试听验证，没有理论保证。

### 起始词典（按需追加，宁少勿多）

| 原文 | 替换为 | 说明 |
|---|---|---|
| 网络用语 A | 同音的常用词 | 模型词表外的词一律按字面念，需要同音替换 |
| 生僻字（歘 / 忒 …） | 同音常用字 | 训练语料里少见的字，模型只能靠上下文猜 |
| 丝滑 | （不替换） | 正常词，别动 |

原则：

1. **只替换会读错的**。替换会改变文本长度，进而改变语速和停顿，动得越多越难对齐。
2. 判断"会不会读错"：**多音字**（行/还/了/得/地）、**网络用语**、**方言字**、**人名错读**。
3. 数字和英文由模型自带的文本正则化处理（`《文明6》`→"文明六"、`QQ`→"Q Q"），不用管。
4. 替换后必须做第 7 步的时长校验（字数变了，语速基准要重算）。

### 4.1 为什么生僻字一定念错（2026-10-27 实测）

CosyVoice2 的前端链路是：`文本正则化（WeTextProcessing/ttsfrd）→ Qwen 字符 tokenizer → token ids`。
**没有拼音层**：`frontend._extract_text_token()` 直接把字符 encode 成 id，模型对每个字的读音
完全来自训练语料。

推论：语料里见得少的字（醺、忱、歘、忒……）只能靠上下文猜。
实测同一段文本在 15 个音色里「微醺」全被听成「微心/微星」——**这是模型级问题，不是某个音色的毛病**，
换音色、改 instruct、加标点都救不回来。

两条应对：

1. **同音字替换**（本节词典），替换后必须用**整段文本**做 A/B 验证。
   不要用「微醺」这种两三个字的短句去验：模型在短句上时长抖动可达 2.5 倍，ASR 也识别不稳，
   得不出结论（实测短句被 whisper 转成「酒飲威胁」这种完全无关的东西）。
2. **要根治只能换引擎**：CosyVoice 3.0 支持拼音/音素注音语法（`报道[j][ǐ]予好评`），
   可以从源头钉死读音。迁移成本与风险见 §10。

## 5. 消歧（第 4 步）——最容易做错的一步

### 5.1 省略号：必须翻译成口语，不能只留停顿

**行业实践（番茄小说听书等）：`角色名：……` 读作「角色名无语」。**

理由：听书用户看不到原文，停顿无法传递"这里是省略号"这个信息，只会以为音频断了。
**所以省略号必须有 verbalization，停顿只是辅助。**

判断主语：看省略号**前最近的一个说话人或动作主体**。

| 原文 | 读作 | 判据 |
|---|---|---|
| `角色A：……` | `角色A无语。` | 单人回应，被噎住 |
| `角色A：……，然后说` | `角色A顿了顿，然后说` | 后面紧跟转折，用"顿了顿"更连贯 |
| `A：……` 后紧接 `B：xxx` | `A 沉默。` + 长停顿 1.2s | 两人对峙，沉默本身就是回应 |
| 叙述中的 `他沉默了……` | 保留"他沉默了"，删省略号 | 已经有词语表达，不用再加 |
| 段落之间单独一行 `……` | **不送合成**，在合并时插 1.2~1.5s 静音 | 这是排版分隔符，没有语义 |

**"无语 / 沉默 / 顿了顿 / 无言"怎么选**：同一章内不要反复用同一个词，会听出模板感。

### 5.2 破折号

| 原文 | 处理 |
|---|---|
| `——`（表示声音延长） | 删掉，靠韵律自然拖长 |
| `——`（表示插入语，前后都断） | 前后各加一个逗号 |
| `——`（对话被打断） | 换成逗号 + 句末加 0.3s 停顿 |

### 5.3 括号补充

`（笑）`、`（叹气）`、`（小声）` 这类舞台提示：

- **优先**转成 instruct 的一部分（"带笑意的语气"），而不是念出来
- 没有对应 instruct 时删掉，宁可丢信息也不要念"括号笑括号"
- **不要**让括号内容进正文（模型会念"左括号笑右括号"）

### 5.4 聊天记录 / 短信 / 弹幕（`昵称：正文`）

微信、QQ 这类"发送者 + 正文"的排版，朗读版的处理方式：

| 部分 | 谁念 | 怎么念 |
|---|---|---|
| `昵称：` | **旁白** | instruct 单独设成「平静地念出屏幕上的昵称，语速偏快，不带情绪」 |
| `正文` | 该角色的音色 | 按台词演，情绪照常 |

三条理由：

1. **不能让角色念自己的昵称**——女声念角色昵称会像在自我介绍。
2. **不要加"说"字**（"角色A说：……"）——聊天记录不是当面说话，加"说"会读成对话，
   一串消息就变成一串尴尬的引语。
3. **昵称必须映射到固定音色**，且和正文里的人物名绑死（同一角色的两个昵称，
   要在角色表里写成一条）。否则同一个角色换昵称就换嗓子。

停顿：昵称与正文之间 **0.1s**（等于冒号），消息之间 **0.45~0.55s**。
给到 1s 以上会像两段无关的旁白，节奏垮掉。

实测（第 0001 章，24 段聊天 + 叙述）：整章 541 字 / 122s / 4.44 字/秒，
两版旁白（男/女）一次跑通，无 instruct 泄漏。

## 6. 按情绪分段（第 5 步）

- **一段一个 instruct**，段内逐句合成（`cosyvoice2-segmented` 的 `max_len=30`）。
- 换段时机：场景切换、情绪转折、对话转叙述、时间跳跃（"片刻后""同一时间"）。
- 段落长度：**100~500 字**。超过 500 字情绪会漂（模型读到后半段会回到中性）；低于 100 字
  会导致频繁加载（每段一个进程，约 40 秒开销）。
- instruct 写法：**具体、口语化、带语速提示**，例如
  - ✅ `用轻松、带点调侃的语气说，像朋友之间聊天，语速正常`
  - ❌ `欢快`（太短，模型自由发挥空间太大）
  - ❌ `用非常非常兴奋并且充满活力地大声喊出来的语气来朗读这段话`（太长，容易泄漏，见 §8）

## 7. 自检与合并（第 7 步）

### 必做自检

| 检查项 | 方法 | 判据 |
|---|---|---|
| instruct 泄漏 | whisper 转录成品，搜指令里的词（`轻松/调侃/语气/旁白/语速…`） | 命中即返工 |
| 语速异常 | 每句「字数 ÷ 时长」 | 同一段内偏离中位数 30% 以上 → 重合成（脚本已内建） |
| 内容完整 | whisper 转录 vs 原文逐句比对 | 少字、串句都要修 |
| 时长合理性 | 总耗时 vs 字数 | 正常 4~6 字/秒 |

### 合并

- **段内句间**：由 `gap_sentence` 控制（默认 0.38s，逗号 0.20s）
- **段间**：0.5s
- **章节间**：1.5~2s
- **末段**：留 0.3s 尾巴，避免播放器一停就断

## 8. 已知坑

1. **instruct 会被念进正文**（实测 22 句里约 1 句）。`frontend_instruct2` 把指令塞进
   `prompt_text` 位置，模型偶尔会接着念。措辞越短概率越低，但不能根治；
   靠「语速异常检测 + 重合成」兜底，靠 whisper 反查验收。
2. **instruct 模式下音色几乎不起作用**：实测换音色后产物时长一字不差。
   想要音色忠实参考音频，用零样本（`cosyvoice2`）而不是 instruct。
3. **逐句与整段的停顿率差别很小**（实测 23.6% vs 23.7%）。别指望"分段"自动带来感情，
   真正决定听感的是 instruct 内容 + 注音 + 消歧。
4. **同一句里混中英文/数字**（`QQ再联系`）语速会异常慢，容易被误判为泄漏，重试一次即可。

## 9. 参数基线

```yaml
variant: cosyvoice2-segmented
max_len: 30            # 每句上限；>40 会回到"一口气"的老毛病
gap_sentence: 0.38     # 句末停顿；0.25~0.5 像朗读，>0.6 一句一顿
speed: 1.0
段间停顿: 0.5
段长: 100~500 字
```

调参顺序：**先调 instruct（影响最大）→ 再调注音/消歧 → 最后微调停顿**。
倒过来做，前面两步一改，停顿又得重调。

## 10. 要不要升级到 CosyVoice 3.0（2026-10-27 调研）

### 事实（官方 README / 论文 arXiv:2505.17589 / 模型卡）

- `Fun-CosyVoice3-0.5B-2512`：2025-12 开源，0.5B，另有 RL 版；入口改为 `AutoModel`。
- 指标（官方表）：test-zh CER **1.45 → 1.21**（RL 版 0.81）；说话人相似度 **75.7 → 78.0**；
  test-hard CER 6.83 → 6.71（RL 5.44）。
- 训练数据 1 万 → **100 万小时**，9 语种 + 18 种中文方言。
- 明确支持 **Pronunciation Inpainting**（拼音 / CMU 音素），官方示例：`对报道[j][ǐ]予好评`。
  具体码表以 `cosyvoice/tokenizer/tokenizer.py` 的注释为准，不要凭猜写。
- Instruct 支持更细：语言、方言、情绪、语速、音量。
- 语音 tokenizer 换成 MinMo 派生的 25 Hz tokenizer；`prompt_text` 需要
  `'You are a helpful assistant.<|endofprompt|>'` 前缀。

### 对我们四件事的影响（分级）

| 我们关心的 | 3.0 会不会改善 | 依据 |
|---|---|---|
| 生僻字发音（微醺→微心） | **会，而且是能力级差别** | 有注音语法，可以从源码层钉死读音；顺便数据量 ×100 |
| instruct 跟手度 | 大概率改善 | 受控维度更多（情绪/语速/音量/方言） |
| instruct 泄漏 | **不一定** | 指令仍然塞在 prompt_text 位置，机制没变；仍需语速异常检测兜底 |
| 声纹插值（blend） | **不能假设** | 我们的 concat-prompt + `flow_embedding` 注入依赖 CosyVoice2 内部结构；3.0 换了 tokenizer，"中点位置"和"变暗"行为都要重新标定 |
| 声音卡（ref.wav + 文本） | 可迁移 | 3.0 仍吃参考音频；但相似度要重测 |

### 建议的推进顺序（不要一把梭）

1. **隔离环境**装 3.0（新 conda env，不覆盖现有 `cosyvoice` 环境），先跑 4 条对比：
   发音（微醺）、instruct 跟手度、语速稳定性、音色相似度。
2. 再验注音语法：拿「微醺」试 `[x][ūn]` 这一类的写法，**以官方 tokenizer 注释为准**。
3. 最后才碰 blend：重跑 2~3 个 ratio，量「变暗」是否仍存在。
4. 四项都过再迁移变体 manifest；不过就维持 2.0 + 同音字词典，成本低得多。

> 提醒：官方 CER 是在标准测试集上算的，里面没有「微醺」这种词。
> CER 从 1.45 降到 1.21 不能证明生僻字一定对——只有注音语法是确定性的解法。

### 10.1 3.0 实测结果（2026-10-28，本机 3060 12GB）

已装：CosyVoice3 仓库（commit 074ca6d）+ env `cosyvoice3`（由 `cosyvoice` 克隆，
transformers 4.51.3）+ `Fun-CosyVoice3-0.5B`（8.3 GB）。旧环境与旧仓库未动。

**结论：音色没变、语速没变、发音变好了——但注音不是 100% 确定性。**

| 项 | 2.0 | 3.0 |
|---|---|---|
| 男主 F0 / 女主 F0 | 147 / 266 Hz | 148.5 / 260 Hz（instruct 模式） |
| 语速 | 3.6–4.9 字/秒 | 3.2–4.9 字/秒 |
| 「微醺」（instruct 模式，13 个音色） | 0/13 读对 | **11/13 读对** |
| instruct 泄漏 | 存在 | **仍然存在**（`frontend_instruct2` 依旧删 `llm_prompt_speech_token`） |

**注音语法（实测，必须照这个写）：**

```
酒饮微[x][ūn]       正确：用音节替换该字，读 wēi xūn
酒饮微醺[x][ūn]     错误：原字 + 注音各念一遍 → 「微熏熏」
酒饮微[xi][ūn]      错误：x 组的韵母是 ü，声母只写 x，写 [xi] 整句读成乱码
```

必须用 `inference_instruct2` 走指令模式；把指令文案塞进 `inference_zero_shot` 的 prompt_text
会因 prompt 文本与语音 token 错位而输出整段乱码（我踩过）。

**还差什么**：13 个里仍有 2 个读成 xū / xīng。注音提高命中率，但不保证。
生产上应加一道「反向转写抽检 → 不合格重渲」的闭环，而不是假设一次就对。

**blend 仍未迁移**：3.0 换 MinMo 25Hz tokenizer，concat prompt + flow_embedding 注入需要重新标定。
