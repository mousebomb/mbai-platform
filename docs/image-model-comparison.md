# 生图模型横向对比（2026-11-16 实测）

数据来自本机 RTX 3060 12GB + 64GB RAM，同一批 288 个历史 prompt 用 `flux3-klein` 重跑，
与原变体产物并排比对（`data/flux3-compare.html`），耗时取自 SQLite 的
`finished_at - started_at`（不含排队）。

样本量提醒：速度是硬数据（几百次执行的中位数）；**质量结论来自约 8 组定向抽样**，
属于定性判断，不是盲测排名。

---

## 1. 决策表（给 Agent 用）

| 需求 | 选谁 | 理由 |
|---|---|---|
| 写实照片、产品图、材质、光影 | `flux3-klein` | 质感/细节最强，1024² 只要 12 s |
| 只要草稿、看构图、批量试方向 | `flux3-klein` 512² | 4.1 s/张，比 z-image 还快一倍 |
| 动漫、插画、图标、线稿、等距建筑、扁平设计 | `z-image-turbo` | 对「某种具体图形风格」的服从性明显更好 |
| 中文文字、海报版式、分栏、标题 | `moss-image-sft` | 唯一有 layout JSON 模式；另外两个都把字写坏或干脆省略 |
| 长 prompt、中英混合的复杂语义 | `qwen-image-aio` | 语义理解最好，代价是 30 s/张 |
| SD1.5 生态、指定 LoRA、特定画师风格 | `sd15-community` | 8 个检查点 + 可选 LoRA，运行时切换 |
| 按指令改图 | `qwen-image-edit-2509` | 2509 + Lightning 4 步 |
| 相似度受控的图生图 | `z-image-turbo-i2i` | `denoise` 控制保留度 |
| 局部重绘 | `z-image-turbo-inpaint` | 蒙版画布 |
| 放大 | `realesrgan-anime` / `realesrgan-x4plus` | 动漫 / 通用 |
| 抠图 | `birefnet`（通用）/ `rembg-anime`（**仅动漫**） | 选错变体会灾难性失败 |

## 2. 速度（中位数，秒）

| 变体 | 512² | 768² | 1024² | 备注 |
|---|---|---|---|---|
| `flux3-klein` | **4.1** | **8.1** | **12.2** | 15 步，n=65/15/186 |
| `z-image-turbo` | 8.1 | 10.2 | 12.2 | 8 步，n=68/3/140 |
| `qwen-image-aio` | — | ~75 | ~30 | 8 步，768² 的 12 个样本多为冷启动 |
| `moss-image-sft` | — | — | 44 | 25 步，n=3，偏少 |
| `moss-image-base` | — | — | 79 | 50 步，n=2，**样本不足** |
| `sd15-community` | — | — | — | **无实测**（历史没跑过） |

三条必须知道的：

1. **`z-image-turbo` 的「快」是相对的**。它是 8 步蒸馏，但每步比 flux3 贵；
   512² 上反而慢一倍。1024² 打平。**再拿「z-image 快」当理由已经站不住**，
   选它的理由只剩「风格服从性」。
2. **首次调用额外 25~40 s**（模型加载）。上表是中位数，p90 里的 42~49 s 都是这个。
   Agent 做延迟预算时要按「第一张贵、后续便宜」算。
3. **`qwen-image-aio` 的 768² 比 1024² 还慢**（75 vs 30）。不是笔误：那 12 个 768² 样本
   基本都落在 ComfyUI 被别的模型挤掉显存、每次重新加载的场景。它是三者里最吃显存的。

## 3. 质量与专长（抽样结论）

### flux3-klein —— 质感最强，但会「自作主张」

- 赢在：材质（金属/水彩/纸张纹理）、光影、景深、细节密度
- 输在：**把抽象风格指令渲染成写实**。同一句「深色蓝图 / 技术工程线稿」，
  z-image 老实画等距线框 + 三面文字，flux3 画成写实金属块 + 全息反光
- 中文文字：会强行写字，但**字形是错的**（招牌笔画错乱）

### z-image-turbo —— 风格服从性最好

- 赢在：明确的图形约束（等距、线框、扁平图标、三面文字、2.5D 斜角）照做率高
- 输在：质感平、细节少、颜色偏饱和，写实类和复杂光影明显不如 flux3
- 定位：**「我要的是这个风格」时用它；「我要好看」时用 flux3**

### qwen-image-aio —— 语义理解最好，性价比最差

- 赢在：长英文 prompt 的多约束（左右对比、笔触粗细变化、留白、配色限制）能完整落地
- 输在：30~90 s/张，26.5 GB 权重占显存，12GB 上靠换页
- 定位：**只在 prompt 复杂度高到其它模型听不懂时才用**

### moss-image-sft —— 文字与版式的唯一解

- 赢在：`prompt` 可以是 Layout JSON（bbox + 每个元素的 caption），分栏/标题/小字可控
- 输在：44 s，非版式任务上没有优势
- 定位：**任何带「排版」「标题」「多个文字区块」的需求**

### sd15-community —— 生态位，不是质量位

- 8 个检查点 + LoRA 下拉，运行时切换，A1111 目录直接链过来
- 质量打不过上面任何一个，但**风格可控性和 LoRA 生态**是唯一入口

## 4. Agent 选型规则

```
需要文字/排版？        → moss-image-sft（Layout JSON）
需要真实质感？          → flux3-klein
需要特定图形风格？      → z-image-turbo
prompt 复杂到听不懂？   → qwen-image-aio
要 LoRA/画师风格？      → sd15-community
只是看构图？            → flux3-klein 512²（4.1 s）
```

两条容易踩的：

1. **别默认用 z-image-turbo 当「快速档」**。512² 它比 flux3 慢一倍，质量还低。
   除非你要的就是它那种扁平/线稿风格。
2. **中文文字不要交给 flux3 或 z-image**。两个都出废图（一个乱码、一个省略），
   这不是调参能解决的，是模型能力边界。

---

## 5. 方法与环境

- 288 个 prompt 取自 713 条历史任务，按 `prompt + width + height` 去重后排除已用 flux3 跑过的 4 条
- 全部 `steps=15`、原尺寸、原 prompt，单 worker 串行，`1002 succeeded / 0 failed`
- 对比页：`data/flux3-compare.html`（左历史原图 / 右 flux3，标注原变体与尺寸）
- 耗时口径：`finished_at - started_at`，不含队列等待与前端轮询
